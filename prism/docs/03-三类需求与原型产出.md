# 03 · 三类需求与原型产出

## 1. 总览

| 场景 | 示例输入 | 处理方式 | 产出页面 | 一致性证据 |
| --- | --- | --- | --- | --- |
| **A 存量页面功能优化** | `examples/需求-存量优化.md` + 原页面截图 + 受控浏览器基线 | 以存量页为基线写「差异蓝图」：变更区块打标记、单独出新旧对照场景 | `asset-ledger.html`（6 态）、`asset-detail.html`（4 态） | 变更区块复用同一批契约组件；对照页两侧同契约渲染 |
| **B 新增功能** | `examples/需求-新增功能.md` + 参考页面截图 + 组件库映射 | 无存量页可比，直接按需求写蓝图；一致性完全交给编译期 | `inspection-plan.html`（6 态）、`inspection-result.html`（4 态） | 样式宪章哈希相同；无新增色值/字号/间距档位 |
| **C 批量新增大量页面** | `examples/需求-批量新增.md` + `examples/batch-matrix.json` | 一份模板 + 一份矩阵，由 `expand.mjs` 确定性展开 12 份蓝图 | `ledger-*.html` 共 12 页（各 4 态） | 结构指纹 `bf10c65a9cf8`，12 页仅 1 种结构 |

合计 **16 个独立 HTML 页面 / 68 个状态面板 / 20 条跳转边**，全部在 `dist/pages/` 下，
从 `dist/index.html` 门户进入，也可逐个双击打开。

## 2. 场景 A · 存量页面功能优化

**输入**：需求文档（6 条变更清单 + 交互状态清单 + 一致性约束）、原页面截图色板、
受控浏览器读到的存量页 computedStyle、组件库映射。

**产出文件**

| 文件 | 状态 | 关键内容 |
| --- | --- | --- |
| `pages/asset-ledger.html` | 常规列表 / 加载中 / 空数据 / 批量选中 / 新旧对照 / 接口异常 | 筛选区增强（5 个条件）、多选表格、批量工具条、语义色状态标签、行操作跳转 |
| `pages/asset-detail.html` | 详情查看 / 编辑态 / 加载中 / 加载失败 | 描述列表、三标签页分组、时间线、转派抽屉、编辑表单校验 |

**需求变更点如何落到原型上**

| 需求编号 | 原型体现 |
| --- | --- |
| C-01 筛选增强 | `filterBar` 区块带变更标记；「查询」走 `scene:loading → wait → scene:default` 状态剧本 |
| C-02 批量操作 | 表格多选列 + 工具条批量停用/导出/全选；「批量选中」状态可演示 |
| C-03 状态语义化 | 表格单元格用 `tag` 契约渲染，配色只取宪章语义变量 |
| C-04 行操作跳转 | 「查看详情」→ `asset-detail`；「发起巡检」→ `inspection-plan` |
| C-05 新增弹窗 | `dialog:create` 内表单，3 个必填字段 + 编号最短长度校验 |
| C-06 异常流 | 「接口异常」状态 + 重试动作串 |

**评审专用能力**：顶部「显示变更标记」给所有变更区块加橙色虚线框与编号气泡；
「新旧对照」场景把改版前后并排，两侧用同一组件契约渲染，差异只来自数据，不会出现"对照图画歪"。

## 3. 场景 B · 新增功能

**输入**：新增功能需求文档（三步流程、字段规则、状态清单）、参考页面截图（仅用于色板校准）、组件库映射。

**产出文件**

| 文件 | 状态 | 关键内容 |
| --- | --- | --- |
| `pages/inspection-plan.html` | ① 基础信息 / ② 规则配置 / ③ 确认提交 / 提交中 / 提交成功 / 草稿态 | 8 个输入字段、必填与格式校验、步骤条推进、规则弹窗、状态剧本 |
| `pages/inspection-result.html` | 结果总览 / 加载中 / 无结果 / 汇总失败 | 4 张指标卡、2 个趋势占位图、明细表、详情抽屉 |

**可真实操作的交互**

- 输入：文本框、下拉、日期、文本域、开关、复选框都是真实控件
- 校验：必填留空、编号少于 4 字符、手机号格式错、阈值填非数字 → 字段级标红 + 轻提示
- 状态剧本：`form:validate:plan → step:2 → scene:step2`；提交走
  `scene:loading → wait:800 → scene:success → toast`
- 跳转：成功态 → 结果看板；结果看板 → 编排页 / 台账页

**一致性说明**：这类页面没有存量页可对照，最容易"画成另一个系统"。
本方案里它和存量页共用同一份 `charter.css`、同一批 `contracts.mjs` 组件、同一个 `runtime.js`，
所以按钮高度、表格行高、标签圆角、弹窗宽度、字号阶梯全都由编译期固定，模型无从改起。

## 4. 场景 C · 批量新增大量页面

**输入**：批量需求文档（12 行页面矩阵）+ 机器可读 `batch-matrix.json` + 统一模板 `_template.json`。

**产出文件**（12 个，各 4 状态：常规列表 / 空数据 / 加载中 / 接口异常）

```
ledger-station.html        站点资产台账      ledger-transformer.html   主变设备台账
ledger-sensor.html         传感设备台账      ledger-network.html       网络设备台账
ledger-cabinet.html        控制柜台账        ledger-power.html         电源设备台账
ledger-line.html           输电线路台账      ledger-meter.html         计量装置台账
ledger-protect.html        保护装置台账      ledger-comm.html          通信设备台账
ledger-spare.html          备品备件台账      ledger-tool.html          工器具台账
```

**批量一致性的三道保证**

1. 模型不逐页写：只确认一次模板语义，12 份蓝图由 `expand.mjs` 用确定性公式生成。
2. 结构指纹：链接器对每页「场景 → 区块序列 → 组件名 + props 键」算 SHA256，
   12 页必须同一个指纹，否则编译中止。报告里显示 `12 页 / 1 种结构`。
3. 真实 DOM 验收：`verify-browser.mjs` 打开两页对比 `.scene` / `.panel` / `.field` / 表格行数与
   computedStyle 背景色，实测结果完全相同。

**每页都具备**：标题区、筛选区（3 条件 + 查询/重置）、工具条、6 列多选表格 + 分页、
行操作、4 个状态、新增台账项弹窗（含校验）、统一侧栏导航、返回总台账与门户。

## 5. 四类交互的覆盖矩阵

| 交互类型 | 实现方式 | 覆盖页面 | 实测 |
| --- | --- | --- | --- |
| **点击** | `data-act` 动作串 + document 事件委托 | 全部 16 页 + 门户（455 个动作串） | 卡片点击、按钮、行操作、标签页、全选、变更标记开关均通过 |
| **输入** | 真实 input / select / textarea / checkbox / switch | 存量筛选区、新增弹窗、编辑态、三步表单、批量弹窗（53 个输入控件） | 真实键入 + 校验标红通过 |
| **状态切换** | 编译期预渲染 `.scene` 面板 + overlay / tab / step / 校验态 | 68 个状态面板 | 空数据、加载→常规、步骤推进、弹窗开关、草稿/成功态通过 |
| **页面跳转** | `navigate:<id>[:<scene>]` 相对路径 | 20 条跳转边，侧栏全局导航 | 门户→页、页→页、页→门户通过 |

> 页面里没有一行手写脚本，全部交互由 `assets/runtime.js` 统一解释；
> 因此 `file://` 下可用，也不需要任何构建或服务器。

## 6. 验收口径与实测

| 口径 | 结果 |
| --- | --- |
| 三类场景都有可操作产物 | ✓ 2 + 2 + 12 页 |
| 四类交互均可用 | ✓ 真实浏览器 18 项点击验收全通过 |
| 新增/改造页与存量页风格一致 | ✓ 同一宪章哈希 `27becad3059bfb20`；`components.css` 色值字面量 0 |
| 批量 12 页保持一致 | ✓ 结构指纹 1 种；真实 DOM 对比一致 |
| 可离线分发 | ✓ 无 fetch/XHR/外链资源，自检断言 |
| 编译期零错误 | ✓ `lint` error 0 / warning 0 |

复现命令：

```bash
node engine/prism.mjs selftest                 # 19 项静态自检
node engine/prism.mjs verify-browser --port=9223   # 需先开带调试端口的 Chrome
```

（`verify-browser` 也可直接 `node engine/verify-browser.mjs --port=9223`。）
