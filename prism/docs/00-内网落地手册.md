# 00 · 内网落地手册（第一次用，先看这份）

> 这份只讲**怎么动手**。方案边界看 `01`，模型约束看 `02`，三类场景看 `03`，
> 蓝图的字段写法看 `04`（那份是给 codeagent 看的，人不用背）。

## 先搞清楚：四件事分别归谁

| 谁 | 做什么 | 不做什么 |
| --- | --- | --- |
| **你（人）** | 登录存量系统、确认宪章草案、把提示词发给 codeagent、看 `lint` 结果、把 `dist/` 发给业务方 | 不手写 HTML/CSS，不画页面 |
| **codeagent3.0 + 清单内模型** | 读需求文档和 `docs/04`，**只写 `blueprints/*.json`** | 不写 HTML/CSS/JS，不改 `foundry/` |
| **Prism 引擎** | `doctor` / `lint` / `expand` / `run` → 产出 `dist/` | 不调用模型、不联网、不要 key |
| **浏览器** | 双击 `dist/index.html` 点着看 | 平时不需要调试端口 |

**最容易断的一环**：模型和引擎之间没有自动连接。是**你**把提示词发给 codeagent，
它写出 JSON 放进 `blueprints/`，引擎再编译。下面第 3 步就是干这个。

---

## 第 0 步 · 把代码弄进内网

三选一：

| 情况 | 做法 |
| --- | --- |
| 内网能连 GitHub | `git clone https://github.com/hfzz01/mcps-skills.git`，然后只用 `prism/` 目录；或稀疏克隆只取 prism |
| 内网连不上 GitHub | 在家把 `prism/` **整个目录**打包，走你允许的摆渡通道拷进去；解压到任意可写目录 |
| 只想给业务方看成品 | 只拷 `dist/` 一个目录，双击 `index.html` 即可，连 Node 都不用装 |

> 不需要 `npm install`，不需要 API key，不需要联网。整个目录是纯文件。

## 第 1 步 · 先体检（10 秒）

在 `prism/` 目录下：

```bash
node engine/prism.mjs doctor
```

看到每一项都是 `✓`、末尾出现「下一步（按顺序做）」就说明环境没问题。
它会顺带告诉你 Node 版本够不够、`dist/` 里有没有成品、目录是不是拷全了。
**这条命令只读，不改任何文件。**

若提示 Node 版本过低：装 Node 20+，或从别的机器拷一个 `node.exe` 用绝对路径调用
（`"D:\tools\node.exe" engine/prism.mjs doctor`）。`lint` / `run` 在 Node 20 就能跑；
只有 `charter --kind=dom` 和 `verify-browser` 需要 22+。

## 第 2 步 · 先看成品，别急着改

**双击 `dist/index.html`**。里面是仓库自带的 16 个示例页面，三类场景都有：

- 点左侧导航切页
- 点顶部「交互状态」按钮切加载 / 空数据 / 异常 / 新旧对照
- 点「新增资产」，留空提交 → 看校验标红；填完再提交 → 看加载态回到列表
- 在「智能巡检编排」里走三步流程
- 点开任意「专项台账」页，看 12 个页面是不是长得一模一样

这一步的目的是**先知道最终产物长什么样**。看到能点能跳，后面的替换就有参照了。

## 第 3 步 · 什么都不改，先跑通一次

```bash
node engine/prism.mjs run
```

`run` = 批量展开 + 编译期校验 + 铸造，日常只敲这一条。预期看到：

```
[1/3] 批量展开 12 份蓝图 → ...\blueprints\batch
[2/3] 校验通过（error 0）
[3/3] 铸造完成：16 页 / 20 条跳转 / 68 个状态
  双击打开：...\dist\index.html
```

看到这个，说明**整套链路在你的内网机器上是通的**。这一步不依赖模型、不依赖登录、不依赖网络。
先跑通再换自己的东西，别一上来就改配置。

## 第 4 步 · 换成你自己的需求（唯一需要动脑的一步）

打开 **`examples/给codeagent的提示词.md`**，里面有三段可以直接整段复制的提示词：

| 模板 | 用在哪 | 复制给谁 |
| --- | --- | --- |
| 模板 A | 存量页面功能优化 | codeagent3.0 会话 |
| 模板 B | 新增功能 | codeagent3.0 会话 |
| 模板 C | 批量新增大量页面 | codeagent3.0 会话 |

**第一次建议这么做**：先别用自己的需求文档，直接用仓库自带的
`examples/需求-存量优化.md` 复制「模板 A」跑一遍，看 codeagent 产出的 JSON 长什么样，
再换成你自己的需求文档。这样出问题能分清是提示词的问题还是需求文档的问题。

流程：

1. 复制模板整段，把里面的 `<<需求文档路径>>` 换成实际路径
2. 粘贴到内网 codeagent3.0，让它执行
3. 它会写出 `blueprints/<页面id>.json`（只写 JSON）
4. 把用不上的示例蓝图**移出** `blueprints/`（不是删引擎文件）。
   注意：批量页 `blueprints/batch/*.json` 是 `run` 每次从 `examples/batch-matrix.json` 重新生成的，
   直接删文件没用，要改矩阵里的 `items` 列表
5. 跑 `node engine/prism.mjs lint`，**必须看到 `error 0`**；有错就按文末「一页纸故障表」改
6. 跑 `node engine/prism.mjs run`，双击新的 `dist/index.html`

> 如果 codeagent 不肯写 JSON、非要直接写 HTML：把提示词里「只输出 JSON 文件，不输出 HTML/CSS」
> 那句再强调一次，或按 `docs/02` 的回退列换清单内另一个模型。**不要自己替它写 HTML**，
> 一写就回到"位置不对、样式不对"那条老路上了。

## 第 5 步 · 校准样式宪章（一次性，可选但建议做）

示例里的配色是通用值。要贴你自己的系统，跑一条提取命令，再人工确认：

```bash
# 从前端仓的 SCSS/LESS/CSS 变量提（最推荐，定制主题指纹在这）
node engine/prism.mjs charter D:/code/ioc-web/src --kind=repo

# 或从原页面截图提主色板（不让模型看图，纯像素统计）
node engine/prism.mjs charter 原页面.png --kind=image

# 或有已登录的调试浏览器，直接读真实 computedStyle（需 Node 22+，人工先登录）
node engine/prism.mjs charter --kind=dom --port=9222
```

产物是 `foundry/charter.draft.css`（草案）。**人工挑出该用的变量，合并进 `foundry/charter.css`**，
然后跑 `lint` 确认 `components.css` 没有色值字面量。这一步做完，后面所有页面自动换皮，
不用逐页改。**不确定的变量就先别动**，用默认值也能出图，只是不够贴。

## 第 6 步 · 交付

```
dist/ 整个目录压缩 → 发给业务方 / 开发 / 领导
```

- 双击 `dist/index.html` 进入门户，或双击 `dist/pages/某页.html` 直接进某页
- `file://` 可用，不用起服务、不用联网
- **不要只发 `index.html`**：页面引用 `assets/` 和 `pages/`，单发会白屏
- 要留证据就一并附上 `dist/consistency-report.md`（含宪章哈希、模型审计、批量结构指纹）

## 换成自己项目时的替换清单

**必须改**

| 文件 | 改成 |
| --- | --- |
| `examples/需求-*.md` | 你的真实需求文档（路径写进蓝图的 `source.requirement`） |
| `blueprints/*.json` | 你的页面：id / title / group / scenes / overlays |
| `blueprints/batch/_template.json` | 批量页的公共结构（只改一次） |
| `examples/batch-matrix.json` | 批量页的 id / 标题 / 编号前缀 / 班组 / 条数 |
| `foundry/charter.css` | 一次性校准成你系统的色值、字号、间距 |

**不要改**

| 文件 | 原因 |
| --- | --- |
| `foundry/components.css` | 只引用宪章变量；要加样式先在宪章加变量 |
| `foundry/contracts.mjs` | 组件契约，模型不能改；要加组件按 `examples/组件库映射.md` 第 4 节走 |
| `foundry/runtime.js`、`engine/*` | 引擎，改了会破坏确定性和一致性保证 |
| `dist/*` | 编译产物，下次 `run` 会整体覆盖；要改就改蓝图 |

## 日常迭代（改需求之后）

```
改 blueprints/*.json 或 examples/batch-matrix.json
        ↓
node engine/prism.mjs lint     （error 必须 0）
        ↓
node engine/prism.mjs run
        ↓
双击 dist/index.html 复核 → 压缩 dist/ 发出去
```

新增一个页面 = 加一份蓝图；批量加 10 页 = 矩阵里加 10 行再 `run`。不需要重新部署任何东西。

## 一页纸故障表

| 现象 | 处置 |
| --- | --- |
| `node` 不是内部或外部命令 | 装 Node 20+，或用 `node.exe` 绝对路径调用 |
| `Cannot find module ...` | 目录没拷全；重新完整拷贝 `prism/`，跑 `doctor` 看缺哪个文件 |
| `lint` 报 `未知组件 xxx` | 让 codeagent 对照 `docs/04` 第 4 节重出蓝图 |
| `lint` 报 `使用了清单外模型` | 蓝图 `generator.model` 改成 `docs/02` 白名单里的五个之一 |
| `lint` 报 `蓝图里出现样式描述` | 模型把 CSS 写进 JSON 了，让它重写；**别改宪章去迁就** |
| `lint` 报 `navigate:xxx 指向不存在的页面` | 补该页面蓝图，或改跳转目标 |
| `lint` 报 `批量组出现 N 种不同结构` | 批量页只能改数据；跑 `expand` 重新从矩阵生成，别手改单页结构 |
| codeagent 只肯写 HTML | 提示词强调「只输出 JSON 文件」，或换清单内另一个模型 |
| `charter --kind=dom` 连不上 9222 | 需要人工用带 `--remote-debugging-port=9222` 的浏览器登录；不方便就改用 `repo` / `image` 两条通道 |
| 页面能打开但样式全无 | `dist/` 没拷全；`assets/` 必须和 `index.html`、`pages/` 一起 |
| 页面能开但点不动 | 浏览器禁了本地脚本，换 Chrome/Edge；或确认 `assets/runtime.js` 存在 |
| 只想给业务方看，不想装环境 | 只发 `dist/`，不需要 Node、不需要模型、不需要引擎 |

---

## 三句话记住

1. **模型写 JSON，引擎出 HTML**，中间靠你把提示词发给 codeagent 串起来。
2. **日常只敲一条 `node engine/prism.mjs run`**；改需求就改蓝图，别改 `dist/`。
3. **交付只发 `dist/` 整个目录**，双击 `index.html` 就能点。
