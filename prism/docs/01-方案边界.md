# 01 · 方案边界

## 1. 定位

Prism 是**需求 → 可交互原型**的编译流水线，不是设计工具、不是低代码平台、不是代码生成器。

| 是 | 不是 |
| --- | --- |
| 把需求文档转成声明式蓝图，再铸造成多页面 HTML | 让模型自由创作 HTML/CSS |
| 用编译期不变量保证页面一致性 | 生成后再靠人/模型检查纠错 |
| 静态、离线、可整目录分发的演示物 | 带后端、能跑真实业务的原型 |
| 给需求评审、开发说明、批量页面交付用 | 给视觉设计师做像素级设计稿 |

**独立性**：本方案从零设计实现，不复用、不兼容、不参考、不读取本仓库内任何既有原型工具、既有配置格式或既有产物。
`prism/` 是一个自包含目录，删掉仓库里其它任何目录都不影响它运行。

## 2. 允许的输入，以及各自的落地边界

| 输入 | 落地通道 | 产出 | 边界（重要） |
| --- | --- | --- | --- |
| **需求文档** | 内网 codeagent 读文档 → 写 `blueprints/*.json` | 页面蓝图 | 文档描述业务意图与状态，不描述样式；模型输出里出现色值/字号/间距即编译失败 |
| **原页面截图** | `engine/extract-image.mjs` 零依赖解码 PNG → 像素量化 | 色板 + 水平分区 → 宪章草案 | **不做语义识别**：不识别"这是表格还是按钮"，不交给任何模型看图 |
| **参考页面截图** | 同上 | 同上 | 同上；参考页的语义由需求文档与人补充 |
| **代码仓探索** | `engine/extract-repo.mjs` 扫 CSS/SCSS/LESS 变量 | 变量清单 + 定制主题判定 → 宪章草案 | 只做静态文本解析，不执行前端代码、不读业务源码给模型 |
| **受控浏览器探索存量页面** | `engine/extract-dom.mjs` 连本机 CDP 读 computedStyle | 真实计算样式 + 几何尺寸 → 宪章草案 | 只连 `127.0.0.1:<port>`；不启动、不关闭、不点击、不提交；需人工先登录 |
| **给定组件库** | `examples/组件库映射.md` 人工校准一次契约 | 组件契约里的 DOM/class/props | 组件库不是运行时依赖；产物不引入组件库的 JS/CSS，内网不必能装包 |

**共同关口**：四条通道产出的是「草案」，必须由人确认后合并进 `foundry/charter.css`。
模型不得改写宪章与契约 —— 这是"贴合存量系统"唯一的人为关口，也是防止模型自由发挥的闸门。

## 3. 一致性如何被保证（四条编译期不变量）

1. **唯一样式源**：整套原型只有 `charter.css` 允许出现颜色、字号、间距、圆角、阴影字面量。
   `components.css` 只能引用变量，链接器逐字节扫描，发现一个 `#hex` / `rgb()` / 裸 `font-size:14px` 就中止铸造。
   所有页面引用同一份 `assets/charter.css`，页面无法覆盖。
2. **组件白名单**：模型只能选用 `contracts.mjs` 里 19 个组件之一，且 props 必须通过类型校验。
   组件的 DOM 结构、间距、状态样式由确定性代码写死，模型无法改写。
3. **链接闭合**：`navigate` / `scene` / `dialog` / `form:validate` 的目标必须存在；
   动作串里的 `wait` 必须是数字；一个目标不存在就编译失败，不会产出"点了没反应"的页面。
4. **结构指纹**：对「场景 → 区块序列 → 组件名 + props 键」做 SHA256（**不含数据值**）。
   批量组要求所有页面指纹相同；只要某页多加了一个按钮、少了一块筛选，指纹立刻不同并中止。

交互同理：所有状态在编译期预渲染成 `.scene` 面板，运行时只切 `display`；
弹层、标签页、步骤条、校验态都是编译产物，不是模型写的脚本。

## 4. 运行边界

- **网络**：引擎零网络请求。`extract-dom` 是唯一需要端口的通道，且只连本机 CDP；
  `compile` / `lint` / `expand` / `selftest` 全程只读写本地文件。
- **依赖**：零 npm 包、零 API key、零云服务、零模型 SDK。只用 Node 内置模块
  （`fs` / `path` / `crypto` / `zlib` / `node:url` / 内置 `fetch` / 全局 `WebSocket`）。
- **版本**：Node 20+ 即可跑 `doctor` / `lint` / `run` / `compile` / `expand` / `selftest` / `charter --kind=repo|image`；
  只有 `charter --kind=dom` 与 `verify-browser` 依赖 Node 22+ 的全局 `WebSocket`（且这两条都不是主流程必需）。
- **产物**：`dist/` 是纯静态文件，`file://` 可打开，无 fetch / XHR / 外链脚本 / CDN 字体。
  自检会扫描全部 HTML 并断言这一点。
- **浏览器**：只复用内网机器上已有的 Chrome/Edge，不分发浏览器二进制，不启动不属于自己的进程。

## 5. 明确不做的清单

| 不做 | 原因 |
| --- | --- |
| 让模型直接写 HTML/CSS | 这正是"位置不对、样式不对"的根源；改成写蓝图后这条通路被物理切断 |
| 图像语义识别 / 视觉模型比对 | 允许的模型清单里没有明确的视觉模型，也不允许引入清单外模型 |
| 像素级 1:1 复刻存量页面 | 需求评审要的是"看起来是同一个系统"，不是复刻；且复刻需要视觉闭环，成本不划算 |
| 真实后端 / 真实接口数据 | 原型要能离线双击打开，接后端就破坏了分发性 |
| 生产可用前端代码 | 契约产出的是演示 DOM，不是框架组件；导代码不在本方案目标内 |
| 模型微调 / 提示词工程竞赛 | 一致性已经由编译器保证，再堆提示词是重复投入 |
| 设计稿文件（Figma/Sketch）导入导出 | 输入边界里没有设计稿，且会引入额外依赖 |

## 6. 适用与不适用场景

**适用**：存量系统功能优化评审、新功能需求演示、按矩阵批量生成同类页面、
给开发说明字段规则与交互状态、离线分发给业务方点着看。

**不适用 / 会失效**：
- 需求文档本身没写清状态与字段 → 模型只能编，蓝图质量取决于输入质量；
  本方案不解决需求不清的问题。
- 存量系统用了完全非标准的自绘组件（如 Canvas 渲染的大屏）→ 契约需要人工新增组件，
  不能指望自动贴合。
- 需要演示真实数据联动、复杂计算、跨页事务 → 超出静态原型能力，应走真实前端 + mock 数据。
- 只有 JPEG / webp 截图且无浏览器可用 → 截图通道只支持 8bit 非隔行 PNG，需先转格式（纯本地转换）。
- 需要多人在线协作编辑原型 → 本方案是文件级产物，走版本库或内网共享盘分发。

## 7. 权限与安全边界

- 引擎不删除 `blueprints/` 下的人工蓝图；`expand` 只清理 `blueprints/batch/` 里非 `_` 开头的生成文件。
- `compile` 会整体重建 `dist/`（交付目录），不要在里面手工改文件，改蓝图后重编译。
- 浏览器探索通道不接管登录动作、不读取密码、不导出 Cookie，只读 computedStyle 与几何尺寸。
- 产物是公开可分发的静态 HTML，不要在蓝图里写真实生产数据、内网地址、账号或密钥。
