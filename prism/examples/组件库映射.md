# 输入 · 给定组件库 → 组件契约映射

> 这是「给定组件库」这一类输入的落地说明。组件库本身不进入原型产物；
> 它只用来**校准** `foundry/contracts.mjs` 里的 DOM 结构与
> `foundry/components.css` 里的 class 命名，校准一次，之后所有页面共享。

## 1. 原则

- 组件库是**事实来源**，不是运行时依赖。原型产物是纯静态 HTML，
  不引入组件库的 JS/CSS 文件，因此不要求内网能装包。
- 映射由人确认一次，模型不得新增或修改契约；模型只能选用契约里的组件。
- 契约里固定了 DOM 结构、合法 props、交互状态；CSS 只引用样式宪章变量。

## 2. 映射表（示例：Element UI 风格组件库）

| 组件库组件 | Prism 契约组件 | 固定 DOM / class | 允许的 props |
| --- | --- | --- | --- |
| PageHeader / 自定义页头 | `pageHead` | `.page-head` / `.page-head__actions` | title, desc, badges, actions |

| ElButtonGroup | `toolbar` | `.toolbar` / `.btn` | count, left, right |
| ElTable + ElPagination | `dataTable` | `.table-wrap > table.table` + `.pager` | columns, rows, selectable, pager, rowActs, opsTitle |
| ElTag | 标签（内嵌于表格单元格） | `.tag.tag--<tone>` | text, tone |
| ElDialog | overlay(`kind: dialog`) | `.overlay > .dialog` | id, title, blocks, foot |
| ElDrawer | overlay(`kind: drawer`) | `.overlay > .drawer` | id, title, blocks, foot |

## 3. 交互状态字典（组件库里怎么写，契约里就怎么固定）

| 状态 | 触发方式 | 产物 |
| --- | --- | --- |
| default | 页面初始 | `.scene[data-scene=default]` |
| loading | 查询 / 刷新 / 提交 | 骨架屏 + 文案 |
| empty | 无数据 | 空状态 + 引导动作 |
| error | 接口异常 | 风险色提示 + 重试 |
| selected | 勾选表格行 | 工具条切换为批量态 |
| success | 提交完成 | 成功态 + 后续跳转 |
| validate-error | `form:validate` 失败 | 控件标红 + 字段级错误文案 |
| dialog / drawer | `dialog:<id>` / `drawer:<id>` | 遮罩 + 弹层 |

## 4. 扩展流程（人工，一次性）

1. 在 `foundry/contracts.mjs` 的 `CONTRACTS` 里新增一个组件：声明 props 类型与 render。
2. 在 `foundry/components.css` 里补 class，只允许引用 `charter.css` 变量。
3. 跑 `node engine/prism.mjs lint`，链接器会校验新组件是否合规。
4. 更新本映射表与 `docs/04-蓝图规格说明.md` 的组件白名单。

**模型侧的边界**：模型只读 `docs/04-蓝图规格说明.md` 里的组件白名单与 props 表，
不读组件库源码，也不改契约文件。这样「让模型参考代码」带来的注意力稀释问题不存在。
